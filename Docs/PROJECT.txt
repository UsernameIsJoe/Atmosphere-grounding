--------------------------------------------------------------------------------
1. ONE-SENTENCE GOAL
--------------------------------------------------------------------------------
From place-linked reviews + photos, learn which visual features co-occur with
atmosphere language mapped to our lexicons (inviting / safe / calm). Output:
strength per lexicon term + ranked supporting image features under each — from
co-occurrence in *our* data, not LLM-invented links.


--------------------------------------------------------------------------------
2. MOTIVATION
--------------------------------------------------------------------------------
People describe places with words like “calm”, “safe”, “inviting”. Photos of
those places contain measurable structure (vegetation, seating, enclosure,
light, …). LLM extracts adjectives/atmosphere language from comments and maps them to
lexicon umbrellas. Vision models measure image features (Layer B ontology).
The learner aggregates place-level co-occurrence between lexicons and features.

The scientific claim: adj/lexicon ↔ feature associations come from corpus
co-occurrence. LLM grounds/extracts text only; it does not invent associations.
SigLIP/DINO are feature and match tools, not substitutes for the co-occurrence
learner. Validate on held-out places (+ shuffle nulls); human checks optional later.


--------------------------------------------------------------------------------
3. WHAT WE ARE NOT DOING
--------------------------------------------------------------------------------
- Not training a text-to-image generator (“paint a park from a review”).
- Not replacing measured features with free-form LLM guesses about visuals.
- Not pre-binding ontology families to atmosphere labels (no hand-coded
  “calm = trees”). Atmosphere ↔ visual links are discovered from data.
- Street View deferred until place-photo path is solid; Google-data constraint,
  not a permanent rejection of pedestrian viewpoint imagery.


--------------------------------------------------------------------------------
4. TWO LAYERS OF THE SYSTEM
--------------------------------------------------------------------------------

LAYER A — Text extraction (LLM extract-only)
  Pre-gates: image/comment usable; review↔photo match → soft weight (z within place)
  Pass A: comment-only → lexicon + adj/phrase + nouns (text-only; mentions.jsonl)
          Nouns: map to ontology add-ons; audit trail; feed Pass B
  Pass B: comment + Layer B top families + add-ons → mentions_fused.jsonl
          Nouns: confirm (full weight) / Pass A carry-over (reduced weight) /
          Layer B-only add; never kill Pass A-only nouns because photo missed them
  Pass B LLM input: top 1–2 families per ontology category at place (~12–24)

LAYER B — Visual category ontology (primary image feature data)
  Per-image family + metric vectors → place-level weighted aggregate for learner
  See configs/visual_categories_v1.yaml; atmosphere-agnostic

IMAGE FEATURE DATA + LEARNER
  Primary: Layer B place profiles
  Add-ons: ontology-mapped nouns from Pass A/B
  Co-occurrence: compute BOTH score tracks (corpus place-equal + within-place rank);
  lightweight aggregates only — choose/blend at analysis or output time


--------------------------------------------------------------------------------
5. RESEARCH STAGES
--------------------------------------------------------------------------------

STAGE 0 — Cambridge pilot (current / near-term)
  Collect parks/plazas (Places API), extract, fuse, ground, correlate, graph.
  Lock visual-category extractors; full-corpus visual_features run; place-holdout
  verification: category feature space vs held-out comments / atmospheres.
  Success bar: human-plausible atmosphere → visual chains, not generic VL prior.

STAGE 1 — Corpus association maps (after more places)
  From accumulated grounded pairs, estimate which ontology features are more
  prominent for a given atmosphere / phrase (lifts, multi-output regression /
  concept-bottleneck style maps). Same data also supports image → keywords
  from *our* feature space (probes / retrieval), not only zero-shot CLIP.

STAGE 2 — Optional LLM narrator (after Stage 1 tables exist)
  Fine-tune (e.g. LoRA) a small instruct LLM so that, given a text passage, it
  *describes* expected visual features in the vocabulary of our ontology.
  Targets must be derived from measured feature profiles (JSON / templated
  text), not from another LLM looking at the photo. Structured predictor
  remains the scientific backbone; LoRA is the fluent interface / distillation.

Data scale (order of magnitude, places):
  Pilot validation: tens–low hundreds
  Solid associations: hundreds–few thousand
  Stronger maps / narrator: few thousand+ with multi-city diversity

6. ARCHITECTURE (LOGICAL)
--------------------------------------------------------------------------------

  [Places API] → places, reviews, photos (same place_id)
        │
        ▼
  [Pre-gates] → soft match weight per review–photo pair
        │
   ┌────┴────┐
   ▼         ▼
 Pass A     Layer B (visual categories on images)
 comment    → family + metric feature vectors per image/place
 only       │
   │         │
   ▼         │
 Pass B ◄────┘   comment + Layer B profile + comment visual add-ons
   │              (refined text side)
   ▼
 TEXT: lexicon/adj mentions          IMAGE FEATURE DATA: Layer B + add-ons
        └──────────┬──────────────────────────┘
                   ▼
        [Co-occurrence learner]
        soft weights · place-normalized feature ranks
                   │
                   ▼
        lexicon strengths + ranked features per lexicon
        held-out place validation · (later) LoRA narrator

9. SUCCESS CRITERIA (PROJECT-LEVEL)
--------------------------------------------------------------------------------
Near-term:
  - Inspectable atmosphere → visual evidence that is locally plausible
  - Ontology extractors stable enough for full pilot feature tables
  - Holdout: visual category space predicts / correlates with held-out text

Longer-term:
  - For input text/place: strength per lexicon + ranked features under each
  - Reverse: feature profile → which lexicons fit our co-occurrence tables
  - Optional LoRA in ontology feature language; targets from measured profiles
