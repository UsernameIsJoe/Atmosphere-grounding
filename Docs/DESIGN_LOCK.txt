--------------------------------------------------------------------------------
1. END GOAL (C)
--------------------------------------------------------------------------------
For a place or text passage, output:
  - Strength score for EACH lexicon atmosphere (inviting / safe / calm — not one winner)
  - Under each atmosphere: ranked supporting IMAGE FEATURES (Layer B ontology families)

Scientific backbone: associations learned SOLELY from co-occurrence in our corpus.
LLM does NOT invent adj ↔ feature links.

--------------------------------------------------------------------------------
2. CORE LEARNING STORY
--------------------------------------------------------------------------------
  TEXT SIDE
    Comments contain adjectives / atmosphere language (not always exact lexicon words).
    LLM extracts that language and maps it to lexicon umbrellas (inviting / safe / calm).
    Optional nouns / visually named things in the comment are add-ons on the text side.

  IMAGE FEATURE SIDE (primary signal)
    Layer B measures each photo → ontology family scores + metrics
    (DINO / seg / SigLIP / image metrics per configs/visual_categories_v1.yaml).
    Aggregated per place (and per review–photo pair with soft match weights).

  ADD-ON (comment ↔ image bridge, not a substitute for Layer B)
    Visual nouns or features mentioned in a comment, and features detected in
    photos that align with that comment, supplement the measured feature vector.
    They do NOT replace Layer B measurements.

  LEARNING
    Observe co-occurrence: lexicon / comment adj  ↔  image feature data
    at place level (location pairing), with SOFT WEIGHTS when review↔photo match is weak.
    Feature ranking under a lexicon: PLACE-NORMALIZED scores for now.

--------------------------------------------------------------------------------
4. PASS A vs PASS B (updated)
--------------------------------------------------------------------------------
  Pass A — LLM reads COMMENT ONLY
           → lexicon atmosphere + phrase + nouns (adj mapped to lexicon)
           Output: mentions.jsonl
           Feeds: TEXT SIDE of co-occurrence only

  Pass B — LLM reads COMMENT + IMAGE FEATURE DATA for that place/pair:
           • Layer B family/metric profile (measured from photos)
           • plus comment-mentioned / comment-aligned visual features (add-on)
           → may refine lexicon assignment, nouns, confidence
           Output: mentions_fused.jsonl (Pass A kept intact)
           Feeds: richer TEXT SIDE; does not replace Layer B as image signal

  Co-occurrence learner uses:
    TEXT: Pass A or Pass B mentions (prefer better text–image match when both exist)
    IMAGE FEATURES: always Layer B (+ add-ons merged into feature data table)

  Legacy note: older pilot code fused DINO object *lists* only; target architecture
  fuses full Layer B ontology profiles. Implementation catch-up TBD.

--------------------------------------------------------------------------------
5. MODEL ROLES (do not conflate)
--------------------------------------------------------------------------------
  LLM        → extract adj → lexicon; optional Pass B refinement using feature context
  Layer B    → primary image feature measurements (families + metrics)
  SigLIP/etc → match weighting, optional localization — not the association answer
  LEARNER    → weighted co-occurrence; place-normalized feature ranks under lexicons

--------------------------------------------------------------------------------
6. PRE-GATES & PAIRING
--------------------------------------------------------------------------------
  1) Image doable (exists, usable public-space photo)
  2) Comment doable (non-empty, about place experience)
  3) Review ↔ photo match → SOFT WEIGHT (not hard drop by default)
  Location pairing remains imperfect (same place_id); weights mitigate noise.

--------------------------------------------------------------------------------
7. SCORING (locked for now)
--------------------------------------------------------------------------------
  Match: soft weight per review–photo pair (e.g. from review↔image cosine).
  Feature rank under lexicon: place-normalized score (compare features within place
  before aggregating co-occurrence across corpus).

--------------------------------------------------------------------------------
8. VALIDATION
--------------------------------------------------------------------------------
  Now: held-out places — lexicon strengths + feature rankings vs held-out data.
  Later: optional human validation; shuffle-null tests for corpus specificity.

--------------------------------------------------------------------------------
9. DATA (Google / pilot)
--------------------------------------------------------------------------------
  Pairing: same place_id; reviews do not describe specific photos.
  Places API: ≤5 review texts, ≤10 photo refs per place (API hard limit).
  Pilot caps (43 places, 3 photos, etc.) = credit budget only — NOT design ceiling.
  Street View: Google data path when place-photo pipeline is solid.

--------------------------------------------------------------------------------
10. LAYER B & LORA
--------------------------------------------------------------------------------
  Ontology v1 fixed; atmosphere-agnostic.
  “Which families work better” = holdout predictive value for lexicon strength.
  LoRA (later): ontology feature language; targets from measured profiles.
