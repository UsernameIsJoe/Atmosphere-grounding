# Calm probability feasibility pilot — 2026-11-23

Small development experiment, not held-out calibration or an image-training experiment.

- Reuse K01–K06 and U01–U06, the exact original target segments plus full reviews. No synthetic inference cases, gates, filters, or replacement review selections.
- Reuse the two v0.5 model tags and verify their recorded digests: Qwen3.8 27B and Gemma4 31B IT BF16.
- Only CALM is assessed. Retain the v0.5 codebook and source/context boundaries. Prior results and prompt files stay frozen.
- Baseline: narrow the existing directional-claim extraction to calm only; retain exact quotes and E/T, and request native token log probabilities. An empty claim set remains possible; separate support and opposition claims remain possible.
- Probability readout: a companion, single-token plain-letter evidence-state classification using the same source inputs and codebook. States are neither / support only / opposition only / both. It is a measurement probe, not an adopted replacement for the extraction pipeline. No numerical self-reported confidence is requested. A JSON-string interface preflight revealed a combined opening-quote/code token in Qwen; that attempt is archived as an interface failure, excluded from main measurements, and not treated as semantic evidence. The revised readout uses no JSON grammar and exactly one output token; semantic evidence rules are unchanged.
- Two code mappings for the readout, with semantic option order unchanged. Canonical: A=neither, B=support only, C=opposition only, D=both. Rotated: B=neither, C=support only, D=opposition only, A=both. This tests code sensitivity; it does not separately isolate option-position sensitivity.
- Planned main calls: 12 cases × 2 models × (one extraction + two readouts) = 72, plus the separately archived failed JSON-string interface preflight. No prompt tuning is performed against its predicted label. Conditions are grouped to reuse the fixed codebook prefix efficiently; no comparison assumes identical prompt length with the earlier three-emotion run.
- Common decoding: temperature 0, seed 42, thinking disabled, context 8192; no probability truncation or repetition penalty. Capture native logprobs and up to 20 token alternatives. Freeze all prompt/schema/input hashes.
- Verify returned logprob signs, token alignment, non-degenerate alternatives and label-token atomicity. Read decision tokens rather than mandatory labels or JSON punctuation. Do not multiply variable-length quote probabilities into claim correctness.
- A complete four-state distribution is normalized over the four native code likelihoods only when all four canonical code tokens occur in the same position's alternatives. Otherwise retain missingness and derive explicit conservative intervals from the top-k cutoff; never replace a missing candidate by zero. Report raw selected-token likelihood separately from normalized class probabilities. Do not claim full soft-target vectors when alternatives are missing.
- Report all raw responses, errors, exact inputs, model digests, runtime versions, per-case states and probabilities, code-mapping sensitivity, extracted evidence, and differences from archived v0.5 calm claim presence.
- Known development concerns include K01 personal-event stress attribution, K04 uncrowded-to-calm inference, and U06 relaxed sitting. These guide qualitative inspection, not independent gold labels. Only explicit user calm adjudications K01=neither and U06=support are used as limited development-reference checks; no 12-case accuracy is manufactured.
